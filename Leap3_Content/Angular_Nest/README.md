# leap-demo

A small **NestJS + TypeScript** backend that demonstrates four things:

1. A basic REST API (`/posts`) with in-memory data and full CRUD
2. Request validation using DTOs (`/posts-dto`)
3. A login endpoint backed by a real **PostgreSQL** database through **TypeORM** (`/login`)
4. A standalone **SQL injection demo** (`sql-demo.mjs`) showing why parameterized queries matter

This guide walks you through recreating the project from scratch, step by step.

## Option B: Recreate from scratch

### Step 1: Create the project and install dependencies

```bash
mkdir leap-demo && cd leap-demo
npm init -y
```

Install runtime dependencies:

```bash
npm install @nestjs/common @nestjs/core @nestjs/platform-express @nestjs/typeorm \
  typeorm pg reflect-metadata rxjs class-validator class-transformer bcrypt
```

Install dev dependencies:

```bash
npm install -D typescript tsx ts-node @types/node
```

> `bcrypt` is installed but not used yet. See [Known limitations](#known-limitations-and-next-steps).

### Step 2: Configure `package.json` scripts

Edit `package.json` so the `scripts` section looks like this:

```json
"scripts": {
  "build": "tsc",
  "start": "node --watch dist/main.js",
  "start:prod": "npm run build && npm start",
  "start:dev": "tsx watch src/main.ts"
}
```

Also make sure it contains `"type": "commonjs"`.

| Script | What it does |
|--------|--------------|
| `npm run build` | Compiles `src/` to `dist/` with `tsc` |
| `npm start` | Runs the compiled app and restarts on changes |
| `npm run start:prod` | Builds, then starts |
| `npm run start:dev` | Runs TypeScript directly with `tsx` and hot reload |

#### `src/main.ts`

```ts
import 'reflect-metadata';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { ValidationPipe } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.enableCors({
    origin: ['http://localhost:4200'], // your frontend URL(s)
    methods: ['GET', 'HEAD', 'PUT', 'PATCH', 'POST', 'DELETE'],
    credentials: true,
  });

  app.setGlobalPrefix('api/v1');

  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
  }));

  await app.listen(3000);
  console.log('listening');
}

bootstrap();
```

What this does:
- Allows a frontend on `localhost:4200` (e.g. Angular) to call the API
- Prefixes every route with `/api/v1`
- Enables global validation. `whitelist` strips unknown fields, and `forbidNonWhitelisted` rejects requests that contain them

#### `src/posts/post.controller.ts` (in-memory CRUD, no validation)

```ts
import {
  Body, Controller, Delete, Get, Param, Patch, Post, Put, Query,
} from '@nestjs/common';
import { AppService } from '../app.service';

@Controller('posts')
export class PostController {
  private posts = [
    { id: 1, title: 'Introduction to NestJS', content: 'NestJS is a Node.js framework built with TypeScript.', createdAt: new Date('2026-10-01') },
    { id: 2, title: 'Understanding REST APIs', content: 'REST APIs use HTTP methods to perform operations on resources.', createdAt: new Date('2026-10-02') },
    { id: 3, title: 'Learning TypeScript', content: 'TypeScript adds static typing to JavaScript.', createdAt: new Date('2026-10-03') },
  ];

  constructor(private readonly aservice: AppService) {}

  // GET /posts
  @Get()
  getAllPosts() {
    return this.posts;
  }

  // GET /posts/search?title=nestjs
  @Get('search')
  searchPosts(@Query('title') title: string) {
    return this.posts.filter(post =>
      post.title.toLowerCase().includes(title.toLowerCase()),
    );
  }

  // GET /posts/1
  @Get(':id')
  getPostById(@Param('id') id: string) {
    return this.posts.find(post => post.id === Number(id));
  }

  // POST /posts
  @Post()
  createPost(@Body() body: any) {
    const newPost = {
      id: this.posts.length + 1,
      title: body.title,
      content: body.content,
      createdAt: new Date(),
    };
    this.posts.push(newPost);
    return newPost;
  }

  // PUT /posts/1  (replace)
  @Put(':id')
  replacePost(@Param('id') id: string, @Body() body: any) {
    const postId = Number(id);
    const index = this.posts.findIndex(post => post.id === postId);
    if (index === -1) return { message: 'Post not found' };

    const updatedPost = {
      id: postId,
      title: body.title,
      content: body.content,
      createdAt: this.posts[index].createdAt,
    };
    this.posts[index] = updatedPost;
    return updatedPost;
  }

  // PATCH /posts/1  (partial update)
  @Patch(':id')
  updatePost(@Param('id') id: string, @Body() body: any) {
    const post = this.posts.find(post => post.id === Number(id));
    if (!post) return { message: 'Post not found' };

    if (body.title !== undefined) post.title = body.title;
    if (body.content !== undefined) post.content = body.content;
    return post;
  }

  // DELETE /posts/1
  @Delete(':id')
  deletePost(@Param('id') id: string) {
    const index = this.posts.findIndex(post => post.id === Number(id));
    if (index === -1) return { message: 'Post not found' };

    const deletedPost = this.posts.splice(index, 1);
    return deletedPost[0];
  }
}
```

> **Important:** the `search` route is declared **before** `:id`. If you reverse them, Nest treats the word "search" as an id.

#### `src/login/login.service.ts`

```ts
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { LoginEntity } from './login.entity';

@Injectable()
export class LoginService {
  constructor(
    @InjectRepository(LoginEntity) private readonly repo: Repository<LoginEntity>,
  ) {}

  async login(username: string, password: string): Promise<{ message: string; token: string }> {
    const user = await this.repo.findOneBy({ username });

    if (!user || user.password !== password) {
      throw new UnauthorizedException('invalid username or password');
    }

    const accessToken = this.issueStubToken('access', username);
    return { message: 'Successful', token: accessToken };
  }

  private issueStubToken(kind: 'access' | 'refresh', username: string): string {
    return `stub-${kind}-token-for-${username}-${Math.random().toString(36).slice(2, 10)}`;
  }
}
```

`findOneBy({ username })` is a parameterized query under the hood, so it is not vulnerable to SQL injection. The token is only a **stub** (a random string), not a real JWT.

## API reference

All routes are prefixed with `/api/v1`.

| Method | Path | Description | Validated? |
|--------|------|-------------|-----------|
| GET | `/` | Hello message | n/a |
| GET | `/posts` | List all posts | n/a |
| GET | `/posts/search?title=...` | Case-insensitive title search | No |
| GET | `/posts/:id` | Get one post | No |
| POST | `/posts` | Create a post | No |
| PUT | `/posts/:id` | Replace a post | No |
| PATCH | `/posts/:id` | Partially update a post | No |
| DELETE | `/posts/:id` | Delete a post | No |
| GET | `/posts-dto` | List posts (service) | n/a |
| POST | `/posts-dto` | Create a post | **Yes**: `title` ≥ 5 chars, `content` ≥ 10 chars |
| POST | `/login` | Log in against Postgres | **Yes**: both fields required strings |

Posts are stored **in memory**, so they reset whenever the server restarts. Also note that `/posts` and `/posts-dto` use **separate** in-memory stores.

## The SQL injection demo

`sql-demo.mjs` is independent of the NestJS app. It uses an in-memory SQLite database, so **no database server is needed**.

It shows two versions of the same lookup:

- **Unsafe:** builds SQL by string concatenation. The input `x' OR '1'='1` turns the `WHERE` clause into something always true, so it returns every user.
- **Safe:** uses a parameterized query (`?`), so the same input is treated as plain text and returns nothing.

### Run it

The demo imports `better-sqlite3`, which is **not** in `package.json`, so install it first:

```bash
npm install better-sqlite3
node sql-demo.mjs
```

Create `sql-demo.mjs` in the project root with this content:

```js
import Database from "better-sqlite3";

const db = new Database(":memory:");
db.exec(`
  CREATE TABLE users (
    username TEXT PRIMARY KEY,
    password TEXT
  )
`);
db.prepare("INSERT INTO users VALUES (?, ?)").run("alice", "mission123");
db.prepare("INSERT INTO users VALUES (?, ?)").run("bob", "wrongpermissions");

// --- VULNERABLE: building SQL with string concatenation ---
function findUserUnsafe(username) {
  const sql = `SELECT * FROM users WHERE username = '${username}'`;
  console.log("Executing:", sql);
  return db.prepare(sql).all();
}

console.log("--- Normal lookup ---");
console.log(findUserUnsafe("alice"));

console.log("\n--- A malicious username ---");
const maliciousInput = "x' OR '1'='1";
console.log(findUserUnsafe(maliciousInput));

// --- SAFE: a parameterized query ---
function findUserSafe(username) {
  return db.prepare("SELECT * FROM users WHERE username = ?").all(username);
}

console.log("\n--- The same malicious input, against the SAFE version ---");
console.log(findUserSafe(maliciousInput));
```

### Expected output

- Normal lookup: returns only `alice`
- Malicious input (unsafe): returns **both** `alice` and `bob`
- Malicious input (safe): returns `[]`

## Known limitations and next steps

This is a learning demo, **not production code**. Things worth improving:

- **Passwords are stored and compared in plain text.** `bcrypt` is already installed; hash on registration and use `bcrypt.compare` on login.
- **The token is a stub**, not a signed JWT. Consider `@nestjs/jwt` plus a guard to protect routes.
- **Database credentials are hard-coded** in `app.module.ts`. Move them to environment variables (e.g. `@nestjs/config` and a `.env` file).
- **No migrations or `synchronize`.** The table is created by hand; for real projects use migrations.
- **`logging: true`** prints every SQL statement. Turn it off outside development.
- **No user registration endpoint.** Users must be inserted via SQL.
- **`/posts` has no validation** and uses `any` for bodies; `/posts-dto` shows the better pattern. The in-memory data is lost on restart.
- Unused leftovers: `MyService`, the unused `AppService` in `PostController`, and some unused imports can be cleaned up.

## Troubleshooting

| Problem | Likely cause / fix |
|---------|-------------------|
| `ECONNREFUSED 127.0.0.1:5432` | Postgres isn't running. Start the Docker container or your local service. |
| `relation "user" does not exist` | You skipped [Step 6](#step-6-create-the-user-table-and-a-test-user). Create the table. |
| `password authentication failed` | Credentials in `app.module.ts` don't match your Postgres setup. |
| `Port 3000 already in use` | Stop the other process, or change the port in `main.ts`. |
| 400 error with "property ... should not exist" | `forbidNonWhitelisted` is on; remove extra fields from your JSON body. |
| `Cannot find module 'better-sqlite3'` | Run `npm install better-sqlite3` before `node sql-demo.mjs`. |
| `bcrypt` fails to install | It compiles native code; make sure build tools are available (Xcode CLI tools on macOS, `build-essential` on Linux). |
| Decorator errors from TypeScript | Confirm `experimentalDecorators` and `emitDecoratorMetadata` are `true` in `tsconfig.json`. |
